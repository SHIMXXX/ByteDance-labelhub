## 当前系统摘要

### 当前已经具备的真实能力
- Owner：任务创建、模板搭建、数据集绑定、任务发布、Reviewer 分配、导出发起
- Labeler：任务领取、多题作答、自动/手动保存草稿、提交、查看 AI / 人工打回理由、修改重提
- Reviewer：待审列表、审核详情、批量处理、AI 结果查看、答案 diff、审核时间线
- 后端：JWT 登录、任务/模板/数据集/提交主链路、AI 异步预审、人工审核记录、多格式导出、关键审计能力

### 当前主要短板
- 第一眼观感仍偏课程作品，整体产品外观、信息架构与页面层级不够完整
- 部分关键页面仍缺失或偏弱，如 Dashboard、我的贡献中心、数据集管理页、导出中心
- 已有能力与前台组织、演示样本、文档口径之间仍未完全收口
- 当前最需要补的是“好看、好讲、好演示、好交付”，而不是继续优先深挖安全和正式化治理

### 当前阶段判断
- 主链路已具备继续产品化升级的基础
- 下一步的核心不是“再证明能跑”，而是“把已有能力包装成完整产品”
- 最终执行应优先围绕高观感、高体验、高演示收益事项展开

## 最终目标

在现有真实链路与工程基础上，把 LabelHub 从“功能型课程作品”升级为“有设计感、体验完整、角色闭环清晰、可顺畅演示、可直接用于答辩交付”的产品化 Demo。

## 总体原则
- 优先做用户可见价值最高的改造：视觉、页面完整度、流程顺滑度、演示讲述性
- 不再把安全深化、正式会话体系、通用 RBAC 作为近期主线
- 尽量基于现有架构小步升级，避免大规模推翻重做
- 所有页面文案、演示脚本、README、用户手册与真实代码能力保持一致
- 所有取舍优先判断：是否提升“第一眼观感 / 核心链路顺滑度 / 角色闭环 / 演示可讲述性”

## 十、基于 `preference_compare` 真实测试数据的流程缺口补充（2026-06-05）
**目标：针对 `preference_compare_workflow.md` 描述的“真实测试数据 → 模板 → 标注 → AI 预审 → Reviewer → 最终导出”链路，仅补充第九点未覆盖的专项流程 / 数据层实现缺口；第九点保留为产品表现与通用工作台增强。**

> 当前状态（2026-06-06）：本节新增实现点已按最小可演示版完成，并已通过后端定向测试、前端定向测试与前端 build 验证；本轮未扩展到通用 `taskType` / ACL / 独立 `FinalResult` 表。

### 原始关键缺口（已按最小可演示版补齐）
- 原数据集导入仍是“文件解析后直接落 Dataset / DatasetItem”，缺少“原始题面字段 / 元信息字段 / 已有标注字段”的识别、分流与导入模式选择。
- 原模板与 Renderer 已支持最小 schema v2、`show_item`、`visibleWhen`、`validationRules`，但还不足以原生表达 `preference_compare` 所需的双回答对比展示、角色字段可见性和更强跨字段校验。
- 原 `llm_assist` 已经接入后端代理调用真实 DeepSeek 服务，但 AI 预审仍尚未接入 Gold Sample 对照逻辑，暂时还不能完整支撑“AI 辅助标注 + Gold 质检”叙事。
- 原 Reviewer 只有通过 / 打回，没有“直接修订并通过”；导出也还没有把最终结果、Gold、多轮历史与 diff 作为稳定结果层重新拼装。

### 新增实现点（2026-06-06 已完成最小可演示版）
- [x] 为数据集导入补“字段角色识别 + 导入模式”能力：已支持自动区分原始展示字段、元信息字段、已有标注字段，并支持“普通待标注 / Gold Sample / 演示数据”三种导入模式，而不再只是把整行 JSON 直接写入 `source_json`。
- [x] 为数据集层补 Gold / 演示答案承载结构：已通过 `Dataset.import_mode` 与 `DatasetItem.reference_answer_json` / `metadata_json` 持久化 Gold / demo 参考答案，确保 Labeler 运行态默认只看到题面字段。
- [x] 为模板设计器补“字段角色映射”与偏好对比展示能力：已新增 `compare_panel`，支持把 `prompt`、`response_a`、`response_b` 配成专用对比展示区，并以 `metadataFields` 承接 `model_a`、`model_b` 等补充字段。
- [x] 扩展模板校验规则表达，覆盖 `preferred / margin / dimensions / safety_flag / annotator_note` 这类跨字段约束：已新增 `min_length / equals_if / not_equals_if`，可承接 `tie ↔ 相当` 等偏好对比核心规则。
- [x] 收口 `llm_assist` 为可讲述的真实链路：若保留该步骤，则至少输出结构化偏好建议并支持“采纳 / 忽略 / 二次修改”回填；若不实现，则从真实演示流程与文档中移除“AI 辅助标注”表述，避免能力穿帮。
- [x] 为 AI 预审补 Gold Sample 对比输入与质检分流：已让 AI 审核读取 `answers + source + reference_answer`，并在本地规则执行器中补最小 Gold 冲突转人工与摘要提示。
- [x] 为 Reviewer 补“直接修订并通过”能力：已允许在审核详情中修改结构化答案后生成最终结果，而不再只限于 approve / reject 两种操作。
- [x] 为结果沉淀补独立“最终结果”快照层：已在通过后固化 `final_answer_json`、`finalized_by`、`finalized_at` 与来源 version 信息，避免后续导出继续直接依赖可变的 `submission.answers_json`。
- [x] 扩展导出 payload 组装能力：已支持导出原始样本字段、元信息、参考答案、原始提交答案与 `finalAnswer` 的聚合结果，形成更接近真实标注平台的最小交付结果。
