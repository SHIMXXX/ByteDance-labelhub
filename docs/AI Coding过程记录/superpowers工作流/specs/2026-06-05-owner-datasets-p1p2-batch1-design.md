# LabelHub P1/P2 第一批（Owner 数据入口）设计稿

> 日期：2026-06-05
> 范围：围绕 `PLANROAD-FINAL.md` 中 P1/P2 的第一批 Owner 数据入口任务，完成“数据集管理页 + 数据集导入向导 + 数据集详情/预览页”的统一产品化设计；UI 风格按 `ui-ux-pro-max` 约束收口，并继续沿用现有 `AppFrame + styles.css` 体系，不引入新 UI 框架。

## 1. 背景

当前仓库在 Owner 侧已经具备：

- 任务创建/列表页中的数据集选择能力
- 任务详情页中的最小数据集预览
- 后端真实数据集接口：列表、题目预览、文件导入

对应已有能力包括：

- `frontend/src/services/api/datasets.ts`
  - `listDatasets()`
  - `listDatasetItems(datasetId, keyword)`
- `backend/app/api/routes/datasets.py`
  - `POST /datasets/import`
  - `GET /datasets`
  - `GET /datasets/{datasetId}/items`

但当前仍缺少一个真正可讲述、可演示、可独立进入的 Owner 数据生产入口：

1. 没有独立的数据集管理页，Owner 只能在任务相关页面被动选择数据集
2. 没有前端导入向导，后端导入能力尚未转化为产品化体验
3. 没有独立的数据集详情 / 预览页，导入结果与样本查看缺少承接

这已经成为 `PLANROAD-FINAL.md` 中 P1/P2 的明显缺口，也会削弱“数据集 → 模板 → 任务 → 发布”的 Owner 主链路讲述性。

---

## 2. 目标

本轮完成后，Owner 侧应新增一组完整、统一风格的数据入口能力：

1. **数据集管理页**
   - 作为 Owner 一级导航入口
   - 支持查看数据集列表、题量、更新时间、说明摘要
   - 支持关键词搜索与快捷进入导入/详情/绑定任务

2. **数据集导入向导**
   - 采用三步向导：上传文件 → 字段/格式确认 → 导入结果
   - 调用已有 `POST /datasets/import`
   - 成功后默认返回管理页，并高亮新导入数据集

3. **数据集详情 / 预览页**
   - 展示数据集基础信息
   - 展示样本条目预览与关键词过滤
   - 提供后续动作：返回列表、去绑定任务

4. **统一 UI 风格**
   - 延续现有 Notion 风格、产品化灰白中性色体系
   - 采用 `ui-ux-pro-max` 收口后的“极简层级 + 数据型后台”组合方向
   - 不引入新的 UI 库、状态库或图表库

---

## 3. 范围边界

### 纳入范围
- Owner 一级导航新增“数据集”入口
- 数据集管理页（列表型运营台）
- 数据集导入三步向导
- 数据集详情 / 预览页
- 与现有数据集 API 的真实联调
- 对应前端测试、构建验证与后续浏览器回归

### 明确不做
- 不做数据集在线编辑/删除/版本管理
- 不做复杂字段映射 DSL
- 不做多文件批量导入
- 不做导入失败后的复杂修复工作流
- 不做独立的数据清洗页
- 不为本轮新引入 UI 框架、表格库、图表库
- 不顺手重构 `OwnerTasksPage` 现有任务创建流程

---

## 4. 方案选择

本轮考虑三种方案：

### 方案 A：独立运营台（两页半）
- 数据集管理页 + 导入向导 + 详情用抽屉或局部预览

**优点**
- 新入口清晰
- 成本适中

**缺点**
- 导入后承接感一般
- 不够完整，不如独立详情页好讲

### 方案 B：嵌入任务页
- 不新增独立数据集模块，把导入/预览/选择继续塞进任务页

**优点**
- 改动最小

**缺点**
- 不符合当前“补齐独立数据生产入口”的目标
- 会继续放大 `OwnerTasksPage` 的复杂度
- 产品化观感不足

### 方案 C：三段式完整页（本轮采用）
- 数据集管理页
- 三步导入向导
- 数据集详情 / 预览页

**优点**
- 完整承接 Owner 数据生产入口
- 与导入成功后的高亮回流逻辑自然衔接
- 最符合 P1/P2 的产品化 Demo 目标
- 便于后续讲述“数据集 → 模板 → 任务”链路

**缺点**
- 比轻量双页方案多一个详情页
- 需要补最小路由与页面状态同步

### 本轮最终采用
**方案 C：三段式完整页。**

用户确认：
- 数据集管理页定位：**运营台**
- 导入方式：**三步向导**
- 导入成功落点：**返回列表高亮新数据集**
- 实施方案：**三段式完整页**

---

## 5. 统一风格说明（基于 ui-ux-pro-max）

本轮不改变全站设计系统，只在现有基础上继续收口。

### 5.1 风格关键词
- Notion 风格
- 极简编辑感
- 数据后台密度
- 灰白中性色
- 深色主按钮 + 少量强调色点缀

### 5.2 页面骨架
沿用现有：
- `AppFrame`
- `styles.css`
- 现有卡片、按钮、badge、输入框样式原语

### 5.3 视觉层级规则
1. 页面头部：大标题 + 一句说明 + 右侧主 CTA
2. 统计层：2~4 张小型指标卡
3. 主内容层：白底卡片 + 细边框 + 柔和阴影
4. 列表行内动作：次级文字按钮 / 描边按钮，避免多主 CTA 干扰
5. 空状态：说明当前缺什么 + 单一主动作（导入数据集）

### 5.4 交互规则
- 每个页面只保留一个主 CTA
- 关键异步动作必须有 loading / success / error 反馈
- 导入向导每步都允许返回上一步，不做不可逆流
- 状态表达不依赖颜色 alone，同时配文案/标签

## 6. 信息架构与路由

本轮建议新增以下 Owner 路由：

- `/owner/datasets`
  - 数据集管理页
- `/owner/datasets/import`
  - 数据集导入向导
- `/owner/datasets/:datasetId`
  - 数据集详情 / 预览页

导航层级：
- Owner 概览
- Owner 任务
- Owner 模板
- **Owner 数据集**（新增）
- Owner 导出

这样可以把 Owner 信息架构统一成：
- 概览（Dashboard）
- 资产（模板 / 数据集）
- 生产（任务）
- 交付（导出）

## 7. 数据集管理页设计

## 7.1 页面目标
让 Owner 能把“数据集”当成独立资产来查看、导入、筛选和进入详情，而不是只在任务创建时被动选择。

## 7.2 页面结构
1. **页面头部**
   - 标题：数据集
   - 说明：集中管理导入样本、查看题量与快速进入任务绑定
   - 主按钮：导入数据集

2. **统计卡片区**
   - 数据集总数
   - 总题量（若当前接口不足，可先按当前页 items 汇总或暂不展示）
   - 最近更新数据集数（可先弱化为“最近导入”计数，必要时后置）

3. **筛选区**
   - 搜索框：按名称 / 描述关键词过滤
   - 刷新按钮

4. **列表区**
   - 列：名称、描述摘要、题量、更新时间、操作
   - 操作：查看详情 / 去绑定任务

5. **空状态**
   - 文案：还没有可用数据集
   - 主动作：立即导入第一份数据集

## 7.3 数据来源
- 主要调用：`listDatasets()`
- 当前接口返回项来自 `GET /datasets`
- 若现有 `DatasetSummary` 中缺少页面所需字段，只允许做最小补齐，不扩到新后端资源模型

## 7.4 关键交互
- 从导入向导返回后，如果携带 `highlightDatasetId`，对应列表行高亮显示并滚动可见
- 搜索默认 debounce 或按钮触发二选一；本轮优先简单实现，不强求复杂搜索体验
- “去绑定任务”先跳转到现有任务页，并带入 `datasetId` 预选语义；若现有任务页暂不支持 query 预填，可先跳任务页并保留后续补口

---

## 8. 数据集导入向导设计

## 8.1 页面目标
把已有导入 API 变成清晰、稳定、好讲述的产品化流程。

## 8.2 向导步骤
### Step 1：上传文件
- 输入：数据集名称、描述（可选）
- 上传文件：支持 JSON / JSONL / Excel（以当前后端真实能力为准）
- 提示：展示受支持格式与大小提示

### Step 2：字段 / 格式确认
- 展示文件名
- 展示将要导入的数据集名称与描述
- 展示格式确认说明
- 若当前后端没有真实字段探测结果，本步不伪造复杂映射器，只如实展示“将按系统默认解析规则导入”

### Step 3：导入结果
- 展示导入成功的数据集名称
- 展示导入题量 / 错误摘要（以当前接口真实返回为准）
- 主动作：返回数据集列表
- 次动作：查看新数据集详情

## 8.3 API 边界
- 调用：`POST /datasets/import`
- 继续沿用 base64 上传协议
- 不在前端额外创造不存在的后端“预校验 / 预解析”接口

## 8.4 状态与错误处理
- 上传中：按钮禁用 + loading
- 导入失败：停留当前步骤并展示错误
- 缺字段/文件缺失：就地校验
- 如果后端只返回摘要错误列表，则原样展示，不包装成不存在的字段级错误 UI

---

## 9. 数据集详情 / 预览页设计

## 9.1 页面目标
承接“从列表进入查看”和“导入完成后的检查动作”，为后续绑定任务提供中转页。

## 9.2 页面结构
1. **头部区**
   - 数据集名称
   - 描述
   - 返回列表
   - 去绑定任务

2. **概览卡片**
   - 题量
   - 更新时间
   - 数据集 ID 或导入来源（若现有字段支持）

3. **样本预览区**
   - 搜索框
   - 预览列表
   - 每条样本展示：序号 + `source` 简要 JSON/键值预览

4. **空 / 错误态**
   - 无样本：提示当前数据集没有可预览题目
   - 加载失败：显示重试

## 9.3 数据来源
- `listDatasetItems(datasetId, keyword)`
- 接口：`GET /datasets/{datasetId}/items`

## 9.4 预览表达
- 不在本轮做复杂 JSON viewer
- 优先做“有限深度的 key-value 预览”或格式化文本块
- 样本过长时截断，保留基础可读性

---

## 10. 与现有页面的关系

### 10.1 OwnerTasksPage
当前任务页中的数据集选择能力继续保留，但角色降级为“任务绑定入口”，不再承担“数据集管理中心”的职责。

### 10.2 OwnerTaskDetailPage
若任务详情页当前已有最小数据集预览，继续保留；本轮不要求把任务详情中的预览完全替换为数据集详情页结构。

### 10.3 导出、模板、任务页
本轮只补数据集入口，不顺手重构导出中心、模板库或任务进度分析。

## 12. 风险与降级策略

### 风险 1：当前 `DatasetSummary` 字段不足
- 处理：优先用已有字段完成 UI；必要时做最小后端字段补齐

### 风险 2：导入 API 返回信息较粗
- 处理：Step 2 不伪造高级解析能力，Step 3 只展示真实导入摘要

### 风险 3：任务页暂不支持 datasetId 预选跳转
- 处理：先保证“去绑定任务”能到达正确入口；预选可作为实现期的小幅增强，若范围过大则后置

### 风险 4：样本预览 JSON 过长
- 处理：使用截断 + 代码块 / 键值块表达，不引入重量级 viewer

---

## 13. 本轮结论

本轮第一批 Owner 数据入口采用：

- **数据集管理页（运营台）**
- **数据集导入三步向导**
- **数据集详情 / 预览页**

统一风格：
- 延续现有 `AppFrame + styles.css`
- 沿用 Notion 风格与极简数据后台表达
- 按 `ui-ux-pro-max` 收口统一层级、CTA 与反馈语义

本轮不做：
- 在线编辑
- 复杂字段映射
- 多文件导入
- 与本轮无关的大规模重构
