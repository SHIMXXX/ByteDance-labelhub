# Owner 任务管理页 Day 1 设计说明

- 日期：2026-05-22
- 负责人：成员 A
- 目标：在不依赖后端与 MySQL 的前提下，把 Owner 主链路第一站做成可演示的最小闭环

## 1. 设计目标与范围

### 1.1 目标
- 基于现有前端骨架，完成任务管理页的最小可演示版本。
- 支持查看任务列表与新增任务。
- 为后续接模板搭建器保留自然的前进路径。

### 1.2 本次范围（必须做）
- 在同一页面内完成“列表态 / 新建态”切换。
- 展示已有 mock 任务列表。
- 提供最小新建任务表单。
- 保存后将新任务加入前端本地状态。
- 新任务默认状态固定为 `draft`。
- 页面中预留发布 / 暂停 / 结束按钮位置，但不实现真实动作。

### 1.3 本次不做（明确砍掉）
- 新增独立路由或独立新建页。
- 接真实后端接口。
- 接 MySQL。
- 做搜索、筛选、分页。
- 做复杂校验、复杂提示、toast、弹窗。
- 实现发布 / 暂停 / 结束状态变更逻辑。

## 2. 方案选择

### 2.1 备选方案
- 单页内嵌表单切换。
- 独立新建页。
- 弹窗表单。

### 2.2 选型结论
本次采用“单页内嵌表单切换”。

原因：
- 当前 [frontend/src/pages/owner/tasks/OwnerTasksPage.tsx](frontend/src/pages/owner/tasks/OwnerTasksPage.tsx) 已有最薄列表骨架，直接在原页面收敛最省改动。
- 第一天目标是可演示闭环，不值得为路由和弹窗分散精力。
- 后续即使要拆页，也可以在功能稳定后再演进，不影响今天的交付。

## 3. 页面结构

页面仅保留一个入口文件：[frontend/src/pages/owner/tasks/OwnerTasksPage.tsx](frontend/src/pages/owner/tasks/OwnerTasksPage.tsx)。

### 3.1 列表态
- 页面标题：任务管理。
- 页面说明：第一版使用 mock 数据。
- 右上角操作按钮：新建任务。
- 下方展示任务卡片列表。

### 3.2 新建态
- 页面标题仍保留在任务管理页内部，不新增路由。
- 页面操作按钮改为：返回列表、保存任务。
- 中间区域展示最小任务表单。

## 4. 数据与状态

### 4.1 初始数据来源
- 初始任务数据继续来自 [frontend/src/mocks/tasks.ts](frontend/src/mocks/tasks.ts)。
- 页面首次渲染时复制 mock 数据到组件本地 state。

### 4.2 本地状态
页面最少维护以下状态：
- 当前视图状态：列表态或新建态。
- 当前任务列表。
- 当前表单值。
- 表单错误信息。

### 4.3 新建任务字段
只保留 4 个字段：
- 标题
- 描述
- 截止时间
- 配额

### 4.4 保存结果
- 保存时前端本地生成一个 id。
- 新任务默认状态固定为 `draft`。
- 新任务插入列表顶部。
- 保存成功后切回列表态。
- 保存成功后清空表单。

## 5. 交互规则

### 5.1 进入新建态
- 用户点击“新建任务”后，页面从列表态切换到新建态。

### 5.2 返回列表
- 用户点击“返回列表”后，页面切回列表态。
- 未要求保留未保存表单内容，默认直接丢弃未保存输入。

### 5.3 保存任务
- 用户填写表单后点击“保存任务”。
- 若校验通过，则新增任务并返回列表。
- 若校验失败，则停留在当前表单态并展示错误提示。

## 6. 校验与错误处理

### 6.1 最小校验规则
- 标题不能为空。
- 截止时间不能为空。
- 配额不能为空，且必须是正数。

### 6.2 错误展示方式
- 仅在页面内展示简短错误提示。
- 不引入 toast，不引入弹窗提示。

### 6.3 成功反馈方式
- 保存成功后直接回到列表态。
- 用户通过看到新任务出现在列表顶部确认保存结果。

## 7. 卡片展示要求

任务卡片至少展示：
- 标题
- 描述
- 状态
- 配额
- 截止时间
- 预留的发布 / 暂停 / 结束按钮位置

说明：
- 按钮第一天只做占位，不绑定真实动作。
- 状态展示继续沿用现有任务状态定义：`draft | published | paused | ended`。

## 8. 实现边界

- 不新建复杂抽象，不为后续接口接入提前设计状态管理层。
- 逻辑优先留在任务页内部，保持第一天实现集中、简单、可控。
- 若需要补少量 mock 类型，可直接在现有 mock / type 文件中最小扩展。

## 9. 验证标准

完成后至少验证以下场景：
1. 初始 mock 任务可正常显示。
2. 点击“新建任务”后可切换到表单态。
3. 填完整 4 个字段后可成功新增任务。
4. 缺少标题时不能保存。
5. 缺少截止时间时不能保存。
6. 配额不是正数时不能保存。
7. 保存成功后新任务出现在列表顶部。
8. 新任务状态显示为 `draft`。

## 10. 成功标准

本次完成的验收口径为：

> Owner 可以在任务管理页看到列表，并通过最小表单新增一条 `draft` 任务。
